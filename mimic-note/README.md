# 미믹노트 — 중앙 컴퓨터

팀원들의 미션·투두리스트를 관리하는 중앙 기록장입니다. 지금까지 정한 내용, 진행 과정, 체크인 방법을 모두 이곳에 모읍니다.
**초안(2026-11-13)** 상태이며, 미믹 클라우드 드라이브의 기존 코드·기획(`docs/`, `server/`, `web/`)과는 분리되어 있습니다.

> ⚠️ 이 저장소는 **공개(public)** 입니다. 텔레그램 토큰·chat id·비밀번호는 절대 파일에 넣지 말고 저장소 비밀값(Secrets)이나 각자 컴퓨터의 `.env` 에만 둡니다. 실제 업무 내용을 담기 전에 비공개 전환을 검토하세요.

## 0. 대전제

[`premise.md`](premise.md) — 이 게임·노트·회사 시스템의 규칙. 접속하면 **가장 먼저** 출력되고, 모든 플레이어·관리자·AI 가 그 세션 동안 따릅니다. 미션은 대전제를 바탕으로 주어집니다. 대전제는 대표관리자(창민)만 고칩니다.

## 게시판

[`투두리스트.md`](투두리스트.md) — 자주 쓰는 가벼운 게시판(정식 미션 전의 할 일·아이디어).

## 1. 접속(로그인) 규칙 — 암호구 `이름 + 저장소 링크`

팀원이 Claude Code 에 정해진 암호구를 보냅니다. 이름은 한글 이름 또는 영문 아이디(대괄호로 감싸도 됨).

```
창민 https://github.com/newcode135-prog/mimic-note
lucas https://github.com/newcode135-prog/mimic-note
```

Claude Code 가 하는 일(저장소 `README.md` 맨 위와 `CLAUDE.md` 에 같은 지시가 있음):

1. 저장소가 없으면 `git clone`, 있으면 `git pull`
2. `node mimic-note/checkin.mjs 민호` 실행
3. **① 대전제**를 먼저 보여 주고, **② 미션 데이터베이스**에서 그 팀원의 남은 미션을 꺼내 Claude Code 가 화면에서 바로 전달 (지금은 텔레그램 없이)

Claude Code 가 전달하는 문구(예):

```
민호님의 미션 1번은 텔레그램 봇 만들기
   텔레그램에서 @BotFather 를 열고 /newbot 으로 봇을 만든 뒤 토큰을 받아요. …
민호님의 미션 2번은 봇에게 /start 보내기
민호님의 미션 3번은 토큰·chat id 전달하고 비밀값 등록
```

Claude Code 를 거치지 않고 직접 실행해도 됩니다.

```bash
node mimic-note/checkin.mjs 민호                 # 남은 미션 보기 + 텔레그램 발송 요청·실제 결과 확인
node mimic-note/checkin.mjs 민호 --no-telegram   # 화면만
```

체크인의 텔레그램은 GitHub Actions 가 보냅니다. 같은 내용을 이미 보냈으면 다시 보내지 않습니다(중복 방지).

## 2. 미션 데이터베이스

모든 미션은 [`data/missions.json`](data/missions.json) 한 곳에 모입니다. 화면의 1번·2번·3번은 **그 사람의 남은 미션 순서**이고, 미션마다 고유 ID(`M-0001`)가 붙습니다.

| 필드 | 뜻 |
| --- | --- |
| `id` | 고유 번호 `M-0001` |
| `assignee` | 담당 팀원 아이디 |
| `order` | 담당자 안에서의 순서 |
| `title` · `detail` | 미션 제목 · 설명 |
| `status` | `todo`(진행) · `done`(완료) · `replaced`(미션설정으로 교체되어 보관 — 지우지 않음) |
| `priority` | `low` 면 후순위(맨 뒤) |
| `createdBy` · `createdAt` · `doneAt` · `doneBy` · `replacedAt` · `replacedBy` | 누가·언제 만들고 끝내고 교체했는지 |

### 대표·관리자가 Claude Code 에 입력하는 말 (Claude Code 가 아래 명령으로 바꿔 실행)

| 입력 | 하는 일 |
| --- | --- |
| `민호 미션설정`<br>`1. 업무 A`<br>`2. 업무 B` | 민호님의 남은 미션을 이 목록으로 교체. 제목이 같은 기존 미션은 ID 유지, 빠진 미션은 `replaced` 로 보관, 완료 기록은 그대로. 같은 목록을 다시 넣으면 변경 없음 |
| `민호 미션추가`<br>`4. 업무 D` | 기존 미션 유지 + 뒤에 추가(이미 있는 제목은 건너뜀). `최우선`이면 맨 앞 |
| `민호 미션완료 2` | 지금의 2번(고유 ID 확인 후) 완료. 남은 번호는 당겨지고 ID 는 그대로 |
| `민호 https://github.com/newcode135-prog/mimic-note` | 체크인(위 1장) |
| `미믹 전체미션` | 5명의 남은·완료 수, 진행률, 상위 3개 |

```bash
node mimic-note/mission.mjs set 민호 <<'EOF'      # 미션설정
1. 로그인 UI 개발
2. 파일 다운로드 API 테스트
EOF
node mimic-note/mission.mjs add 민호 <<'EOF'      # 미션추가 (--top: 맨 앞)
4. API 성능 최적화
EOF
node mimic-note/mission.mjs add 민호 "제목" "설명"   # 한 개만 추가
node mimic-note/mission.mjs done 민호 2             # 완료(여러 개: done 민호 2 3, ID: done 민호 M-0002)
node mimic-note/mission.mjs low 민호 1              # 후순위
node mimic-note/mission.mjs list [민호] · all       # 보기(이 폴더 기준 — 먼저 git pull)
```

바꾸는 명령은 이렇게 동작합니다.

```
mission.mjs set/add/done/low
  ① 이 컴퓨터의 gh 로그인 계정 확인 → 저장소 쓰기 권한 + members.json 의 github 로 본인·역할 확인
  ② GitHub main 의 최신 missions.json 을 읽어 적용 → 검사(validateDb) → 파일 sha 를 붙여 저장(커밋)
     그사이 누가 바꿨으면 GitHub 가 거절 → 최신본에 다시 적용(최대 3번). 강제로 덮어쓰지 않음
  ③ 그 커밋으로 GitHub Actions "미믹노트 알림"이 돌고, 끝나면 팀원별 실제 발송 결과를 화면에 출력
```

- 미션 만들기·정하기·후순위는 **관리자(창민·민호·유리)만**, 완료는 **본인 미션 또는 관리자**만 할 수 있습니다.
- 팀원은 텔레그램 봇에서 관리자에게 **미션 요청**(status `requested`)만 보낼 수 있고, 관리자가 수락하면 `todo`, 거절하면 `declined` 가 됩니다(대전제 2·3번 — 배정은 관리자). 요청·수락·거절은 봇이 저장하므로, 팀원이 JSON 을 직접 고쳐 올린 요청은 권한 없는 변경으로 막힙니다.
- 권한은 `--by 이름` 이 아니라 **GitHub 인증 계정**으로 확인합니다. 명부에 GitHub 아이디가 없는 팀원(네이뜬·루카스)은 아이디를 등록해야 명령을 쓸 수 있습니다.
- 로컬 확인은 1차 방어일 뿐이라, GitHub Actions 가 push 마다 **push 한 계정의 권한을 다시 확인**합니다(아래). 직접 JSON 을 고쳐 push 해도 권한 없는 변경은 알림이 나가지 않고 실행이 실패로 표시되며 대표관리자에게 경고가 갑니다. 그 뒤 알림은 **관리자 이상이 다시 저장(또는 되돌리기)할 때까지 보류**됩니다 — 관리자의 다음 저장이 그 상태를 승인한 것으로 봅니다.
- ⚠️ **한계(정직하게)**: 저장소 쓰기 권한이 있는 사람은 확인 코드(`notify.mjs`)나 워크플로 자체를 고쳐 push 할 수 있고, 저장소 비밀값(봇 토큰·chat id)도 자기 워크플로로 꺼낼 수 있습니다. 그래서 이 확인은 **실수·직접 수정을 잡는 감지 장치**이고, 완전한 차단은 GitHub 쪽에서만 됩니다 — 쓰기 권한은 믿는 사람에게만 주거나, 개인 저장소 대신 조직 저장소 + 보호 규칙(CODEOWNERS 승인)을 쓰세요.

### 텔레그램 자동 발송 (GitHub Actions `.github/workflows/mimic-checkin.yml` → `notify.mjs`)

```
main 에 missions.json·members.json 변경 반영 (push)          10분마다 정기 검사 (schedule)        체크인·재전송 (workflow_dispatch)
        └──────────────────────────────┬──────────────────────────────┘
  ① 장부의 "마지막으로 확인된 커밋" → 지금 main 까지를 push 단위로 나눔
     (누가 push 했는지 = 저장소 활동 기록 — [skip ci] push·force push·PR 병합도 남음)
  ② push 마다 그 push 를 한 GitHub 계정의 권한을 "확인된 상태의 명부"로 확인
       관리자: 추가·수정·후순위 / 팀원: 본인 미션 완료만 / 삭제·명부 변경: 대표관리자 / 저장소 주인 계정: 모두
     권한 없는 변경·깨진 데이터는 확인된 상태로 올리지 않음 → 발송 안 함 + 실행 실패 + 대표관리자 경고
     main 기록이 다시 쓰이면(force push) 저장소 주인이 실행할 때까지 아무것도 보내지 않음
  ③ 확인된 변경 중 텔레그램 메시지가 실제로 달라진 팀원만 고름 (안 바뀐 사람에게는 안 보냄)
  ④ 그 팀원의 "확인된 최신 상태"를 그 사람 chat id 로만 sendMessage → 응답(ok·message_id·chat.id)까지 확인 → 결과를 로그·요약에 기록
  ⑤ 장부(Actions 캐시)에 사람별 마지막 발송 내용의 해시 → 같은 내용 재발송 방지
     미연결·토큰 없음·실패는 '보류' → 다음 실행(정기 검사 포함)에서 재시도
```

- 텔레그램 오류: 429(요청 제한)는 `retry_after` 만큼 기다려 재시도, 5xx·네트워크 오류는 재시도, 403(차단) 등은 실패로 기록. 한 사람의 실패가 다른 사람의 발송을 막지 않습니다.
- 동시 실행은 한 줄로 세우고(concurrency), 중간 실행이 합쳐져 취소돼도 다음 실행이 그 구간을 push 한 사람별로 확인합니다.
- 정기 검사는 바뀐 것·보류된 것이 없으면 아무것도 보내지 않습니다. GitHub 의 예약 실행은 **정확히 10분 간격이 보장되지 않습니다**(늦어지거나 건너뛸 수 있음). 공개 저장소는 60일간 활동이 없으면 예약 실행이 꺼집니다. 끄기: 저장소 변수 `MIMIC_NOTE_SCHEDULE=off`. **비공개로 바꾸면** Actions 무료 시간(월 2,000분)을 정기 검사가 대부분 쓰므로 끄거나 간격을 늘리세요.
- `pull_request` 로는 실행하지 않습니다(외부 PR 코드에 비밀값이 닿지 않음). 권한은 `contents: read`, `actions: read` 뿐입니다.
- 수동 재전송: `node mimic-note/telegram.mjs resend 민호` (같은 내용이어도 다시 보냄)
- 장부(확인된 기준 커밋·발송 기록)는 Actions 캐시에 있어 7일간 한 번도 읽히지 않으면 지워집니다(정기 검사가 켜져 있으면 계속 읽힘). 장부가 없으면 **안전하게 멈추고**(확인 안 된 상태를 보내지 않음), 저장소 주인 계정이 한 번 실행하면 다시 시작합니다: `gh workflow run mimic-checkin.yml -R newcode135-prog/mimic-note` 또는 그 계정으로 미션 명령 1번. 이때 발송 기록도 없어져 같은 내용이 한 번 더 갈 수 있습니다. 처음 배포(저장소 주인이 PR 병합)도 같은 방식으로 시작됩니다.

메시지 모양(데이터에서 계산 — 상위 3개 + 설명은 눌러서 펼치기, 4번부터는 "추가 미션"에 접힘):

```
🎯 MIMIC NOTE

👤 민호님의 미션

1️⃣ 로그인 UI 개발

2️⃣ 파일 다운로드 API 테스트

3️⃣ 모바일 화면 검수

━━━━━━━━━━

📊 진행률 0/3
📌 남은 미션 3개
```

**미션을 끝내면**(`민호 미션완료 2`)

- 그 팀원에게: 맨 위에 `✅ 방금 완료: 파일 다운로드 API 테스트` 가 붙은 새 목록(완료한 미션은 빠지고 진행률이 오름). 다시 보낼지는 "방금 완료" 줄을 뺀 목록으로 판단하므로, 나중 체크인이 같은 목록을 또 보내지 않습니다.
- 그 미션을 준 사람(`createdBy`)에게: `✅ MIMIC NOTE 완료 알림 — 👤 민호님이 미션을 완료했어요 • … 📊 민호님 진행률 1/3 · 남은 미션 2개`. 담당자 본인이 만든 미션이거나 스스로 끝낸 경우는 보내지 않고, 다른 사람이 대신 완료 처리했으면 "(유리님이 완료 처리)"처럼 적습니다. 완료했다가 되돌린 미션은 알리지 않습니다. 받을 사람이 미연결이면 표시만 하고 버리고(`미믹 전체미션` 으로 확인), 발송이 실패하면 다음 실행(정기 검사 포함)에서 다시 보냅니다.

### 봇 서버 — 클라우드플레어 워커(24시간)

`worker/index.mjs` 는 클라우드플레어 워커(무료)에서 도는 봇 서버입니다. 텔레그램 웹훅으로 버튼·미션 명령·연결을 처리하고, GitHub Actions 의 미션 알림을 중계합니다. 아래 "코어 오브 미믹노트 봇"(`bot.mjs`)과 같은 판단 로직(`core.mjs`)을 씁니다 — 서버를 쓰면 `bot.mjs` 는 끕니다(웹훅과 동시에 쓸 수 없음).

```
텔레그램 ──웹훅──▶ 워커 /telegram  ── 역할·미션은 GitHub(Actions 가 확인한 커밋)에서 읽기, 저장은 GitHub API(확인 버튼 뒤)
GitHub Actions(notify.mjs) ──▶ 워커 /relay/send(팀원 아이디로 발송) · /relay/verified(확인한 커밋 알림)
```

- 설치: `node worker/setup.mjs` (클라우드플레어 로그인 → KV → 배포 → 비밀값 → 이 컴퓨터의 연결·링크 옮기기 → 웹훅). 다시 실행해도 됩니다. GitHub 토큰만 바꾸려면 `--new-github-token`.
- 새 팀원 연결: 관리자가 봇에 `루카스 연결링크`(또는 `/link 루카스`) → 24시간짜리 일회용 링크를 그 사람에게만 전달 → [시작] 하면 연결되고 지금 미션이 바로 갑니다. 서버를 쓰는 동안 `telegram.mjs connect` 는 이 방법을 안내만 합니다.
- 이미 연결된 사람을 다른 텔레그램으로 옮기는 링크는 **대표관리자만** 만들 수 있고, 옮기면 예전 대화에 "연결이 해제됐어요" 알림이 갑니다. 연결은 사람마다 따로 저장해 동시에 연결해도 섞이지 않습니다.
- 저장 계정: 워커의 GitHub 토큰 주인(저장소 관리자)으로 저장하고 커밋에 실제로 준 사람을 적습니다. main 에 확인 안 된 변경이 있으면 저장하지 않고, 저장은 **확인한 커밋 바로 위에만** 만들어 빨리감기로만 반영합니다(그사이 누가 main 을 바꾸면 처음부터 다시 확인).
- 비밀값: `WEBHOOK_SECRET`(텔레그램), `RELAY_SECRET`(Actions — GitHub 비밀값 `NOTE_RELAY_SECRET`), `IMPORT_SECRET`(설치 컴퓨터와 워커에만). 비밀값이 없거나 짧으면 서버는 모든 보호된 요청을 거절합니다. 한계: `RELAY_SECRET` 은 Actions 비밀값이라 저장소 쓰기 권한자는 꺼낼 수 있습니다(봇 이름으로 메시지 보내기 정도) — 쓰기 권한은 믿는 사람에게만.
- 무료 한도: 하루 요청 10만·KV 쓰기 1천·요청당 CPU 10ms — 5명 팀이면 넉넉합니다.
- 서버가 없을 때(비밀값 `NOTE_RELAY_URL` 없음) Actions 는 예전처럼 텔레그램에 직접 보냅니다.

### 코어 오브 미믹노트 봇 — 버튼으로 미션 주고받기

봇 대화창 아래에 팀원 이름봇(**[창민봇] [민호봇] …**)과 **[📋 팀 현황] [📤 보낸 미션]** 버튼이 늘 떠 있습니다. 본인 이름봇은 내 미션과 ✅ 완료 버튼, 다른 사람 이름봇은 그 사람 미션과 (역할에 따라) 📨 미션 주기·요청 버튼을 보여 줍니다(아래 "미션 앱" 표). 단체방에서는 답하지 않습니다.

```bash
node mimic-note/bot.mjs                  # 이 컴퓨터에서 켜기(켜져 있는 동안만 답함)
bash mimic-note/bot-install-macmini.sh   # 맥미니에 상시 실행으로 설치(권장) · --status · --remove
```

- 봇은 **한 컴퓨터에서만** 켭니다(텔레그램은 한 곳에만 업데이트를 줌). 봇이 켜져 있으면 새 팀원 연결은 `node mimic-note/telegram.mjs connect --no-wait` 로 링크만 만들고, 팀원이 링크로 [시작]하면 **봇이 연결**합니다(링크를 만든 컴퓨터에서 봇이 돌아야 함).
- 봇이 켜질 때 봇 이름을 "코어 오브 미믹노트"로, 명령어 메뉴(/start 메뉴, /me 내 미션, /team 팀 현황, /sent 보낸 미션)를 설정합니다.
- 이름봇 화면은 누를 때마다 보냅니다(자동 알림의 중복 방지와는 별개). 미션이 바뀌면 오는 자동 알림은 그대로 GitHub Actions 가 보냅니다.
- 버튼(✅ 완료·📨 주기/요청·수락/거절·🔄)은 **봇이 켜져 있을 때** 바로 동작합니다. 꺼져 있는 동안 누른 버튼은 텔레그램이 24시간 보관했다가 봇이 켜지면 처리합니다(수락·거절은 그때 바로 저장, 완료는 확인을 다시 물음). 목록·완료 알림은 봇과 상관없이 GitHub Actions 가 보냅니다.
- 맥미니로 옮길 때: 맥미니에 이 저장소를 받고, 연결한 컴퓨터의 `.env`(봇 토큰·chat id)를 안전하게 옮긴 뒤(채팅·저장소에 붙여 넣지 않기) 설치 스크립트를 실행합니다.

**미션 앱 — 버튼으로 주고받기**

| 누르는 것 | 하는 일 |
| --- | --- |
| 본인 이름봇(예: 민호봇) | 내 미션 + **[✅ 1] [✅ 2] …** 완료 버튼(확인 한 번 더) · 관리자는 받은 요청 **[✅ 수락] [❌ 거절]** |
| 다른 사람 이름봇 | 그 사람 미션 보기 + 관리자는 **[📨 미션 주기]**, 팀원은 관리자에게 **[📨 미션 요청]** → 내용을 적어 보내면 확인 후 저장 |
| 📋 팀 현황 | 사람마다 남은·완료·받은 요청 수, 텔레그램 미연결 표시 |
| 📤 보낸 미션 | 내가 준·요청한 미션이 수락 대기·진행 중·완료·거절 중 어디인지 |
| 🔄 새로고침 | 그 화면을 최신으로 |

- 알림: 새 미션·목록 변경·완료 알림(미션을 준 사람에게)은 GitHub Actions 가 보내고, 그 목록 메시지에도 ✅ 버튼이 붙습니다. 요청이 오면 받은 관리자에게, 수락·거절되면 요청한 사람에게 **봇이 바로** 알립니다.
- 한 번 보낸 글은 **미션 하나**입니다(휴대폰에서 여러 줄로 써도 하나). 여러 개를 한 번에 주려면 `1. 첫째` `2. 둘째` 처럼 번호(또는 `-`)를 붙입니다.
- 팀원 → 관리자 요청은 수락해야 미션이 되고(수락한 미션은 목록 맨 뒤, 같은 제목의 미션이 이미 있으면 수락 대신 거절), 팀원끼리는 주고받지 않습니다(대전제). 한 사람당 대기 요청은 10개까지, 한 번에 20개까지 보낼 수 있습니다.
- 확인된 커밋 위에 봇이 직접 만든 커밋(과 미션 데이터를 안 바꾼 코드·문서 커밋)만 있으면 Actions 확인 전이라도 이어서 저장·표시하므로 버튼을 연달아 눌러도 됩니다. 내용이 아니라 커밋으로 판단하므로, 확인 전의 변경을 남이 되돌려(revert) 예전과 같은 내용이 돼도 봇은 그 위에 저장하지 않습니다. 봇이 만든 커밋 목록은 봇 컴퓨터의 `~/.mimic-note/core-bot-trusted.json` 에 남아 다시 켜도 이어집니다.
- ⚠️ main 의 force push 는 GitHub 설정(Settings → Rules → main 에 "Block force pushes")으로 막아 두세요. 확인 전의 봇 저장을 force push 로 지우면 봇과 Actions 가 알아채지 못할 수 있습니다. 다른 곳(Claude Code·직접 push)에서 방금 저장한 내용이 있으면 Actions 확인(보통 1분 안)까지 "잠시 뒤 다시"라고 답합니다.

**텔레그램으로 미션 주기**(관리자): 봇 대화창에 `창민 이거 결제해줘` (또는 `창민한테 …`, 여러 개는 줄바꿈해서 `1. …`)를 보내면 봇이 "창민님에게 이 미션을 줄까요? [✅ 보내기] [취소]" 로 묻고, 보내기를 누르면 GitHub 에 저장됩니다. 그러면 GitHub Actions 가 창민님에게 맨 위에 `🆕 새 미션: 이거 결제해줘 (민호님이 줌)` 이 붙은 목록을 보냅니다.
- 보낸 사람은 텔레그램 연결(일회용 코드)로 확인하고, 관리자(창민·민호·유리)만 바로 줄 수 있습니다. 팀원이 `민호 이거 봐줘` 처럼 보내면 요청이 됩니다. 확인 버튼은 10분 뒤 만료됩니다.
- 저장은 봇이 도는 컴퓨터의 gh 계정(저장소 쓰기 권한 필요)으로 하고, 미션의 `createdBy`·커밋 메시지에는 실제로 준 사람을 적습니다(`by 유리·텔레그램, newcode135-prog 계정으로 저장`).
- 받는 사람 메시지의 "🆕 새 미션" 줄은 다른 사람이 준 미션에만 붙습니다(스스로 넣은 미션 제외).
- 봇에서도 같은 명령을 씁니다(모두 확인 버튼 뒤 저장): `민호 미션완료 2`(본인 미션 또는 관리자) · `창민 미션추가` + 목록 · `창민 미션설정` + 목록(남은 미션 교체, 기존은 보관).
- 봇은 역할·미션을 **GitHub Actions 가 확인한 상태**(+ 봇이 이번 실행에서 직접 저장한 내용)에서 읽습니다. main 에 권한 없는 변경 같은 확인 안 된 변경이 있으면 봇은 저장하지 않습니다(그 변경을 봇 저장으로 승인해 버리지 않게).
- 봇이 저장에 쓰는 gh 계정은 저장소 관리자이거나 관리자 팀원이어야 합니다(아니면 저장 전에 거절).

**팀원에게 전달하는 법**: 처음 한 번은 각자 **본인 연결 링크**(connect 가 만든 것)를 개인 메시지로 보내고, [시작]을 누르면 연결과 함께 버튼판이 뜹니다. 이미 연결된 사람은 봇 대화창에서 /start 를 누르면 버튼판이 다시 뜹니다.

### 텔레그램 연결 (저장소 주인이 한 번, 팀원은 링크만 누름)

1. 텔레그램 **@BotFather** → `/newbot` → 봇 토큰 받기 (미믹 클라우드 서비스 봇과 **다른** 봇)
2. 저장소 주인 계정(`newcode135-prog`)으로 gh 로그인된 컴퓨터의 **본인 터미널**에서:
   ```bash
   node mimic-note/telegram.mjs connect
   ```
   - 토큰을 화면에 안 보이게 입력 → `getMe` 로 진짜 봇인지 확인 → `.env`(git 제외)와 GitHub 비밀값 `TELEGRAM_BOT_TOKEN` 에 등록
   - 아직 연결 안 된 팀원마다 **일회용 연결 링크**(24시간)가 나옵니다 → 각자에게 **본인 링크만** 개인 메시지로 전달
3. 팀원이 링크를 열고 **[시작]** → 봇에 `/start <코드>` 가 가고, 코드가 맞을 때만 그 텔레그램 계정을 그 팀원에게 연결합니다.
   코드 없는 `/start`, 이미 쓴 코드, 만료 코드, 단체방, 이미 다른 팀원으로 연결된 계정은 거절합니다.
4. 연결되면 chat id 가 GitHub 비밀값 `TELEGRAM_CHAT_ID_<아이디>` 에 팀원별로 따로 등록됩니다(서로 덮어쓰지 않음). 터미널에 그 사람의 텔레그램 이름이 나오니 본인이 맞는지 확인하세요.
5. 상태: `node mimic-note/telegram.mjs status` · 다시 연결: `connect --relink 민호`
6. 연결은 **한 컴퓨터에서만** 하세요. "이미 다른 팀원으로 연결된 계정" 확인은 그 컴퓨터의 `.env` 기준이라(GitHub 비밀값은 읽을 수 없음), 다른 컴퓨터에서 하면 이 확인이 빠집니다. 맥미니의 패시브 스킬이 텔레그램을 쓰려면 맥미니에서 같은 명령으로 연결하세요.

권한이 없어 비밀값 등록이 실패하면 GitHub → Settings → Secrets and variables → Actions 에서 같은 이름으로 직접 등록하면 됩니다. 토큰·chat id 는 저장소·이슈·대화에 절대 붙여 넣지 않습니다.

## 2-1. 작업 기록과 패시브 스킬 [자동 다운로드]

```
플레이어마다 "자기 칸"에만 기록 ── data/players/<아이디>/work.json
  node mimic-note/work.mjs 루카스 라벨링 강의-001 시작
  node mimic-note/work.mjs 루카스 라벨링 강의-001 완료
        ▼  commit·push
⏱ 패시브 스킬 [자동 다운로드] (맥미니, 10분마다) ── passive/auto-download.mjs
  ① git pull 로 모두의 최종 기록 받기
  ② 규칙(passive/rules.mjs)으로 계산 → data/auto/todos.json (이 파일은 타이머만 씀)
  ③ 바뀐 사람에게만 알림
        ▼
🎮 1번 게임기: Claude Code — 암호구로 접속하면 ①대전제 ②미션 ③자동 투두
📱 2번 게임기: 텔레그램 / 맥 알림창 — "투두가 바뀌었어요" · "⚡ 더 중요한 일이 생겼어요"
```

**규칙 v1** (`passive/rules.mjs`)

| 규칙 | 언제 | 결과 |
| --- | --- | --- |
| E1 | 같은 대상·같은 단계를 2명 이상이 진행 중 | ⚡ 더 중요한 일(둘 다) + AI 검토 후보 |
| E2 | 이미 누가 끝낸 일을 다른 사람이 진행 중 | ⚡ 더 중요한 일 |
| T1 | 관리자가 배정한 미션 | 투두 맨 앞 |
| T2 | 내가 진행 중인 작업 | 이어서 하기 |
| T3 | 한 단계(라벨링→압축→업로드)가 끝났는데 다음 단계를 아무도 시작 안 함 | 앞 단계를 끝낸 사람에게 다음 단계 제안 |

- 알림은 **내 투두가 바뀌었을 때**와 **더 중요한 일이 생겼을 때**만 갑니다. 같은 내용은 반복해서 보내지 않습니다.
- 앞 회차가 안 끝났으면 이번 회차는 건너뜁니다(중복 실행 방지). 한 사람의 기록 파일이 깨져도 전체는 계속 돕니다.
- 맥미니 설치: `bash mimic-note/passive/install-macmini.sh` · 상태: `… --status` · 제거: `… --remove`
- 텔레그램: 맥미니 저장소 폴더의 `.env` 에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` (git 에 안 올라감)
- 규칙이 애매한 경우(AI 검토 후보)는 [AI 하네스 v1](harness/README.md)이 처음 볼 때 한 번 Claude 에게 묻고, 제안을 관련 플레이어의 ⚡ 더 중요한 일에 붙입니다. 결정은 관리자가 `harness.mjs verdict` 로.

## 2-2. [사고력 게임]

플레이어와 AI 가 `[ ]` 언어로 겨루는 게임. 각자 자기 칸(`data/players/<아이디>/games.json`)에 저장되고, 접속하면 **④ 마지막 사고력 게임**이 바로 보입니다.

- 출제자의 답은 **봉인**: `답 + 소금`의 sha256 만 공개 → 상대가 답한 뒤 공개하면 누구나 대조할 수 있음(답을 나중에 바꾸지 못함)
- `node mimic-note/game.mjs <이름>` 보기 · `answer "<답>"` 답하기 · `reveal "<답>" <소금>` 공개 · `judge player|claude|draw` 판정

**게임 규칙 v2** (대표관리자 창민, 2026-11-13 — G-001 이후 적용)

1. **목적** — 능력 증명이 아니다. **서로에게 지금 가장 필요한 것을 묻는 시스템**이다.
2. **숨은 의도** — 질문으로 상대의 yes/no 프레임을 확인한다. 답이 no 라면, 그 틀 밖에서 **모두가 만족하는 세 번째 제안**을 낸다([더블 바인드], [우문현답]).
   예: *Sometimes you win, sometimes you learn.* — 나에게만 이득인 답을 넘어 **서로 다 이득**인 답.
3. **문제의 형태** — 그 주제를 **가장 빠르게 실행 모델(MVP)까지** 만들 길을 찾는 질문이어야 한다.
4. **답의 형태** — 본질을 이해했음을 **[꿰뚫었다 [꿰]]** 형태로 보인다(본질을 꿰고, 바로 실행으로 꿴다).
5. **승리 조건** — 상대에 대한 **완벽한 인정**. 서로 인정하면 둘 다 이긴다. 인정이 안 되면 진 게 아니라 배운 것(learn)으로 기록한다.
6. **패배 인정** (2026-11-13 추가) — 어느 쪽이든 패배를 인정하면 **그 결정이 무조건 최종 판정**이 된다. 답 전·판정 후에도 가능하고, 이후 판정으로 바꿀 수 없다. `node mimic-note/game.mjs <이름> concede <player|claude> [G-001] "이유"`
7. **먼저 하기** — 플레이어가 "먼저 해 줘"라고 하면 Claude 가 봉인 답을 먼저 공개한다(`reveal … --first`, 기록에 남음).

## 4. 초월 시스템 — 지금까지 정한 방향

- 미믹노트는 사람들의 미션을 관리하는 **중앙 컴퓨터**입니다.
- 플레이어(팀원)는 각자 아이디가 있고, **그 아이디의 최종 투두리스트 + 모두가 함께 수행 중인 공통 미션**을 바탕으로 투두가 갱신됩니다.
- 갱신 주기: **10분에 1번** (패시브 스킬)
- 텔레그램 메시지는 각자의 최종 투두리스트에 따라 다르게 갑니다. 액티브 스킬 예: `[상태창]` → 레벨·퀘스트 창
- 투두를 수행하면 **보상**을 줍니다 — 이것이 초월의 핵심. 레벨 규칙은 나중에 천천히 추가.
- 데이터는 여러 명이 동시에 올려도 쌓이지 않게 **압축·소거** 합니다.
- 인원: 10명 이내로 시작 (지금 5명)
- 상세 개발 지시서: [`guides/초월-가이드-1번.md`](guides/초월-가이드-1번.md) (MIMIC TASK 가이드)
