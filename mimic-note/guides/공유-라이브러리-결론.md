# 미믹 클라우드 새 저장소 형태 — 공유 라이브러리 (결론 · 2026-11-14)

> 상세 설계: [newcode135-prog/mimic PR #97](https://github.com/newcode135-prog/mimic/pull/97) 의 `docs/LIBRARY_DESIGN.md`
> 상태: **설계 초안 — 구현 전.** 아래 "결정 필요"를 관리자가 정하면 구현 시작.

## 1. 아이디어

- **원본 공간(라이브러리, 예: 1TB)** 에 영상을 한 번만 올린다.
- 유저는 영상마다 **개별 링크**를 받아, 그 영상을 **자기 계정 공간에 "담아"** 스트리밍으로 본다.
- 몇 명이 담아도 디스크에는 **원본 1벌**뿐 → 저장 공간은 라이브러리 크기를 넘지 않는다.
- 기존 PikPak식 기능(클라우드 다운로드·업로드·공유)은 그대로 두고, **`library` 모듈 하나를 더한다.**

## 2. 왜 가능한가 (지금 미믹 코드)

- 파일 본문을 SHA-256 지문으로 **1벌만** 저장하고, 각 유저의 파일은 그 지문을 가리키는 목록 한 줄이다.
- 720p 변환본·썸네일도 지문 기준으로 한 번만 만든다.
- → "담기" = 본문 복사 없이 목록 한 줄 추가. 드라이브·플레이어·이어보기·시청 기록은 그대로 쓴다.
- 원본을 고화질로 바꾸면 담은 모든 사람에게 한 번에 반영, 원본을 내리면 "볼 수 없는 영상"으로 표시.

## 3. 저장 공간 vs 대역폭 (중요)

- **저장**은 1벌이지만, **시청은 볼 때마다 서버 → 시청자 기기로 실제 전송**된다(물탱크 1개, 수도꼭지마다 물이 흐름).
- 예: 339MB 영상을 100명이 보면 저장 339MB · 전송 약 34GB. 1080p ≈ 4~8Mbps/명 → 동시 시청자 × 비트레이트 ≤ 서버 업로드 회선.
- 맥미니(집·사무실 회선)는 동시 수십~200명이 한계 → **본 제품은 다른 서버**로(출시 전 결정).

## 4. CDN 대비 설계

- 재생 주소를 `/v/<원본 지문>/<화질>/seg-00001.ts?exp=…&sig=…` 로 바꾼다.
  - 경로가 누구에게나 같음 → CDN 이 한 번 받아 모두에게 재사용(원본 서버는 영상당 거의 1번만 전송).
  - 권한은 서명(만료시각 + 서버 비밀키)으로 확인 → 링크를 못 받은 사람은 못 본다.
- 1단계는 미믹 서버가 직접 응답, 2단계(출시 전)에 CDN 을 앞에 세우기만 하면 됨.
- 후보: Cloudflare R2(+CDN), Bunny CDN/Stream, AWS CloudFront+S3, 국내 CDN — 가격·약관은 서버 정할 때 조사.

## 5. 진행 순서

1. **지금:** 공유 라이브러리 기능(원본 1벌 + 담기 링크 + 서명 재생 주소)을 테스트 서버에서 구현
2. **출시 전:** 본 서버·오브젝트 스토리지·CDN 선정 → 데이터 이전(Node + SQLite + 데이터 폴더라 서버를 바꿔도 시스템·화면 그대로)

## 6. 결정 필요 (관리자)

## 7. 참고 — 화면·화질 테스트

main 코드 그대로 별도 테스트 서버에서 1080p 60fps 영상(Big Buck Bunny, CC BY)을 Premium 테스트 계정으로 올려 **원본 그대로(1920×1080, 끊긴 프레임 0)** 재생 확인. 캡처와 재현 방법은 PR #97 의 설계 문서 부록. 무료 회원 720p 변환(`veryfast`·CRF 23)은 화질이 떨어질 수 있어 개선 검토.
