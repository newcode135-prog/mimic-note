# MIMIC TASK — 5인 사내 협업 시스템 개발 지시서

## 프로젝트 목적

GitHub 저장소 `https://github.com/newcode135-prog/mimic`를 기반으로 회사 구성원 5명이 사용할 내부 업무관리 시스템 **MIMIC TASK**를 구현한다.

단순한 투두리스트가 아니라 각 구성원이 자신의 업무를 빠르게 파악하고, GitHub 개발 현황을 공유하며, 중복 개발을 예방하는 협업 워크스페이스가 목적이다.

화면은 실제 업무에 사용하는 고급 SaaS 제품처럼 깔끔하고 직관적으로 제작한다. 게임처럼 진척도가 보이는 경험은 제공하되 캐릭터나 과한 애니메이션은 사용하지 않는다.

## 1. 기존 프로젝트 분석

코드를 수정하기 전에 반드시 다음 파일을 확인한다.

- `README.md`
- `docs/MIMIC_PLAN.md`
- `docs/features.json`
- `package.json`
- `server/core/`
- 기존 GitHub Issues 및 라벨·마일스톤

기존 미믹은 클라우드 드라이브 개발 프로젝트이며 현재 GitHub Issues에 88개의 작업이 등록되어 있다.

기존 서비스 코어와 충돌하지 않도록 사내 업무관리 시스템을 독립된 모듈과 화면으로 구성한다.

원래의 기능 명세 및 개발 규칙을 보존하고 무단으로 변경하지 않는다.

각 사용자는 자신의 개인 업무 공간을 가진다.

초대 링크 또는 개인 URL을 통해 접속할 수 있지만 URL에 포함된 이름만으로 인증을 허용하지 않는다.

최초 접속 시 안전한 초대 인증을 거치도록 구현하고, 이후 로그인 세션을 유지한다.

## 3. 개인 투두리스트

로그인 시 GitHub에 등록된 현재 작업을 불러와 다음과 같이 정리한다.

- 지금 시작해야 하는 작업
- 진행 중인 작업
- 우선순위가 높은 작업
- 다른 작업의 완료를 기다리는 작업
- 검토가 필요한 작업
- 완료한 작업

각 업무 카드에는 다음 정보를 표시한다.

- 작업명
- GitHub Issue 번호 및 바로가기
- 담당자
- 우선순위 P0/P1/P2
- 진행 상태
- 담당 모듈
- 관련 파일
- 선행 작업
- 체크리스트
- 최종 변경 시각

사용자가 마지막으로 보던 화면과 정렬 상태를 유지한다.

## 4. GitHub 동기화

GitHub Issues를 실제 개발 작업의 기준으로 사용한다.

기존 `P0`, `P1`, `P2`, `area:*`, `module:*`, 마일스톤을 활용하고 기존 라벨 체계를 훼손하지 않는다.

개인 계정과 GitHub 사용자명을 관리자가 매핑할 수 있게 한다.

Issue 배정과 상태 변경은 필요한 권한이 있을 때 GitHub에 반영한다.

GitHub Webhook으로 Issue, Pull Request, 관련 변경 사항을 동기화한다.

10분 주기로 정합성을 재검사하고 오류 시 재시도한다.

중복 Issue 생성, 자동 무단 종료, 작업 삭제를 금지한다.

`docs/features.json`과 GitHub Issue의 기존 관리 규칙을 확인하고, 상태 변경이 서로 충돌하지 않게 설계한다.

## 5. 10분 자동 중복 점검

서버에서 10분마다 자동 검사를 수행한다.

검사 대상은 다음과 같다.

1. 같은 Issue를 여러 사람이 동시에 진행하는지
2. 작업 제목과 설명이 실질적으로 중복되는지
3. 동일 모듈이나 파일에서 변경 충돌이 발생할 가능성이 있는지
4. 진행 중인 Pull Request 간 수정 파일이 겹치는지
5. 선행 작업이 끝나지 않았는데 후속 작업을 진행하는지
6. 팀원에게 배정되지 않아 누락된 중요 작업이 있는지

동일 모듈 담당만으로 충돌로 확정하지 않는다. 실제 근거를 확인해 충돌 확정, 충돌 의심, 정상 협업을 구분한다.

충돌 발생 시 관련 팀원, Issue, 파일 경로, 원인을 표시하고 적절한 작업 분리 방법을 제안한다.

AI는 업무 배정과 코드 변경을 임의로 실행하지 않는다. 충돌에 대한 최종 판단은 담당자 또는 관리자가 한다.

10분 검사 외에도 작업을 시작하거나 PR을 생성하는 시점에 즉시 중복 여부를 확인한다.

## 6. 업무 시작 및 점유 기능

팀원이 업무 시작 버튼을 누르면 해당 업무에 현재 작업 중인 담당자가 표시된다.

작업 시작 시 중복 및 선행 작업 검사를 실행한다.

다른 사람이 동일 업무를 진행하고 있다면 작업 충돌 가능성을 먼저 알린다.

필요하면 관리자가 담당 범위를 나눌 수 있도록 한다.

작업 완료 시 GitHub Issue 및 PR 상태와 테스트 결과를 확인한다.

테스트되지 않은 코드를 자동으로 완료 처리하지 않는다.

## 7. Telegram 연동

사내 업무관리 전용 텔레그램 봇을 구현한다.

BotFather에서 발급한 토큰은 서버 환경변수로 보관한다.

각 구성원이 최초 1회 텔레그램 계정과 내부 계정을 안전하게 연결한다.

로그인 성공 시 개인 또는 설정된 관리자 채널에 다음 형태의 알림을 전송한다.

"[이름]님, 로그인되었습니다.
현재 담당 업무와 진행 상황을 확인했습니다."

팀원별 개인 알림과 관리자용 전체 상태 알림을 분리한다.

필수 명령어:

- `/status`: 전체 업무 진행 상황
- `/mine`: 내 업무
- `/today`: 오늘 처리할 업무
- `/conflicts`: 현재 중복·충돌 의심 작업
- `/health`: 업무관리 서버 및 GitHub 연동 상태

중복 위험, 중요 작업 지연, 작업 완료, 연동 장애 시 알림을 제공한다.

같은 경고를 매 검사마다 반복 발송하지 않도록 중복 알림 방지 기능을 구현한다.

로그인 알림은 새 인증 세션 생성 시 보내며 페이지 새로고침만으로 반복 발송하지 않는다.

## 8. UI/UX 디자인

제품 이름은 `MIMIC TASK`.

전체 디자인은 고급스러운 미니멀 업무관리 SaaS를 기준으로 한다.

- 밝고 정돈된 배경
- 절제된 포인트 색상
- 읽기 편한 타이포그래피
- 선명한 정보 위계
- 적절한 여백
- 모바일 반응형 지원
- 자연스럽고 빠른 전환 효과
- 불필요한 그래픽 최소화

핵심 메뉴:

1. 내 업무
2. 팀 전체
3. 작업 충돌
4. 진행 현황
5. 알림 및 설정

팀원 5명을 볼 수 있는 전용 공간을 제공한다.

업무 완료율, 오늘의 진행률, 개인 작업 현황을 자연스럽게 시각화한다.

게임형 보상 요소는 진행률과 완료 경험에 한정하며, 업무 수행을 방해하는 장식은 배제한다.

실제 디자이너가 설계한 서비스처럼 디테일까지 완성한다.
